# OSMOO Website Master PRD

## 1. Product definition
OSMOO is a premium AI Operating Companion. The website is the public product surface, account control plane, commercial platform, software distribution system, and ecosystem hub.

## 2. Primary user journeys
### Visitor
Landing -> understand value -> explore capabilities -> inspect security -> pricing -> download or sign up.

### New account
Sign up -> verify email -> onboarding -> optional Pro purchase -> download -> account dashboard.

### Existing user
Sign in -> dashboard -> subscription -> downloads -> releases -> skills -> developer features.

### Pro purchase
Pricing -> checkout -> provider -> verified webhook -> transaction -> entitlement -> UI refresh -> receipt/email.

### Developer
Developer onboarding -> project -> API key -> docs -> skill package -> validation -> submission -> review/publish.

### Admin
Secure authentication -> admin shell -> dashboard -> operational action -> step-up auth if sensitive -> audit event.

## 3. Product pages
Home, Product, Capabilities, Security, Pricing, Download, Sign In, Sign Up, Verify Email, Reset Password, Account, Billing, Downloads, Skills, Skill Detail, Developer Portal, API Docs, Status, Contact, Terms, Privacy, Cookies, Security Contact, Admin.

## 4. Conversion requirements
Every primary page has one clear next action. Never use deceptive urgency. Early-access limits must be calculated from authoritative records.

## 5. Account requirements
Users can inspect profile, sessions, subscription, entitlements, downloads, API keys, skill access, security settings, and deletion controls.

## 6. Commercial requirements
Pricing displayed to the user must be consistent with the provider checkout configuration. Final price/tax/currency must come from the server/provider. Client-supplied price is ignored.

## 7. Distribution
Users must receive only valid, released artifacts. Download authorization can depend on account entitlement, but public release metadata must never expose private storage credentials.

## 8. Ecosystem
Skills are versioned, permission-declared, publisher-attributed, integrity checked, and reviewed before public distribution.

## 9. Trust
The site must communicate security architecture honestly: no invented certifications, benchmarks, customer logos, reviews, or uptime numbers.

## 10. Accessibility and localization
Core flows must work with keyboard navigation, screen readers, reduced motion, and responsive layouts. Architecture should permit localization later.

## 11. Success metrics
Activation, download completion, verified-account rate, checkout success, subscription lifecycle reliability, release adoption, skill installation success, support burden, error rate, and security incidents.

## 12. Explicit non-goals
Do not build a generic chatbot page, fake AI demo, fake admin dashboard, fake payment flow, or client-only authorization.
